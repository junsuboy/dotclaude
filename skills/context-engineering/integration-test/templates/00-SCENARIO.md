## 3. 후조치 프로토콜 — "현장 수정 → 형상 반영" (실패 시 필수)

특정 INT 스텝이 실패하면 **그 자리에서 멈추지 말고** 아래 5단계를 밟는다.

| 단계 | 내용 | 기록 위치 |
|------|------|-----------|
| ① 실패 확정 | INT-XX 의 어느 기대결과가 어긋났는지 + 근본 원인 | EVIDENCE-LOG `후조치` 표 |
| ② 현장 핫픽스 | 실기기/환경에서 직접 수정하여 통과시킴. **무엇을 어떻게 바꿨는지 원문 그대로** 기록 | EVIDENCE-LOG `후조치` 표 |
| ③ 형상 반영 | 핫픽스를 **원천 소스**(생성기·스크립트·코드)에 반영 → 다음 빌드부터 자동 생성. 브랜치/커밋/PR | 해당 Feature `11-HISTORY` |
| ④ 재검증 | 형상 반영본으로 재빌드 → INT-XX 재실행 → PASS | EVIDENCE-LOG (재시도 행) |
| ⑤ 문서 동기화 | 변경이 동작·계약을 바꿨으면 해당 Feature `90-SUMMARY` / `30-QA_HANDOFF` 갱신 | 해당 Feature 폴더 |

> 핵심: **현장 수정으로 끝내지 않는다.** 현장 수정은 형상(소스)에 반영되어야 "통과" 로 인정한다. ②(현장)와 ③(형상)이 모두 기록돼야 INT-XX 는 PASS.

## 4. 증거 규약

- 증거 파일은 이 폴더의 `evidence/` 에 둔다. 파일명: `INT-XX_<짧은설명>.{log,png,txt}` (예: `INT-08_docker-info-driver.txt`).
- 명령 출력은 `command | tee evidence/INT-XX_*.log` 로 동시에 남긴다.
- 각 INT 스텝의 **성공 증거** 항목에 적힌 산출물이 모두 모이면 그 스텝은 PASS.
- 스텝별 PASS/FAIL·증거 파일명·후조치는 `01-EVIDENCE-LOG.md` 에 기록한다.
